# Инструкции для агента

## Контекст проекта

- Это статический bio-link сайт без package manager, сборки и backend.
- Главный пользовательский файл — `js/config.js`; не переносить настройки в HTML/CSS/`script.js` без необходимости.
- Структура: `index.html`, `css/style.css`, `js/config.js`, `js/script.js`, `assets/**`.
- Не считать README доказательством текущего поведения: проверять исходники и браузерный результат.

## Границы изменений

- Перед правкой прочитать `README.MD`, релевантные исходники и проверить `git diff`/статус, если репозиторий Git доступен.
- Не перезаписывать чужие незакоммиченные изменения и не менять изображения/видео без явного запроса.
- Сохранять текущие визуальные эффекты, конфигурационные ключи, пути ассетов и публичные ссылки, если задача не требует обратного.
- Не добавлять зависимости, фреймворки, build system, backend или внешние CDN без обоснованной необходимости.
- Для динамического текста использовать безопасные DOM API (`textContent`, `setAttribute`); не вставлять значения конфигурации через `innerHTML`.

## Рабочий процесс

1. Зафиксировать цель, затронутые файлы, доступные маршруты, состояния UI и критерии готовности.
2. Проверить фактические DOM-селекторы, конфигурационные контракты, ссылки на ассеты и обработчики событий.
3. Внести минимальное изменение в существующую архитектуру; не маскировать недоступный runtime или внешний ресурс заглушкой без явной пометки.
4. Проверить синтаксис, локальную отдачу по HTTP, браузерные состояния и ошибки консоли/сети.
5. В отчёте разделить выполненные проверки, непроверенные области и известные ограничения.

## Команды проверки

| Проверка | Команда или действие |
|---|---|
| Синтаксис JavaScript | `node --check js/config.js; node --check js/script.js` |
| Локальный HTTP | `py -m http.server 8000` из корня, затем открыть `http://127.0.0.1:8000/` |
| Проверка ресурсов | DevTools → Network: нет 404 для CSS, JS, изображений, шрифта и видео |
| Smoke-тест UI | открыть entry screen, нажать вход, проверить звук, карточку, аватар, бейджи, Discord-блок, ссылки, громкость |
| Адаптивность | проверить узкие и широкие viewport; отдельно проверить touch/keyboard, если менялась интерактивность |
| Доступность | проверить `lang`, заголовок, `alt`, `aria-label`, фокус клавиатуры, контраст и `prefers-reduced-motion` |

- Если `node`/`py` недоступны, выполнить доступную эквивалентную проверку и явно сообщить об этом.
- Не открывать сайт через `file://` для итоговой проверки: видео, шрифты и сетевые ресурсы требуют HTTP.
- После изменения ассетов проверить регистр имён и относительные пути на окружении с чувствительной к регистру файловой системой.

## Веб-разведка и доказательства

- Для реконструкции или проверки внешнего сайта сначала составить manifest маршрутов, состояний, API, ассетов и ограничений доступа.
- Разделять: подтверждено браузером, подтверждено исходниками, предположено и недоступно для проверки.
- Не обходить CAPTCHA, DDoS-защиту, авторизацию, IP-ограничения или приватные API; использовать только разрешённые данные и bounded fallback.
- Не объявлять результат «1 в 1» по одному скриншоту или успешной загрузке: нужны проверка маршрутов, интеракций, сетевых запросов и ошибок.
- Для удалённых ресурсов фиксировать URL, HTTP-статус и влияние отказа; не добавлять секреты, токены и персональные данные в код или отчёты.

## Правила реализации

- Сначала исправлять причину, затем добавлять защиту от деградации; не скрывать ошибки пустыми `catch` и молчаливыми fallback.
- Сохранять порядок загрузки `config.js` перед `script.js` и не ломать контракт `CONFIG`.
- Для кликабельных внешних ссылок сохранять `target="_blank"` вместе с `rel="noopener noreferrer"`.
- Не отключать accessibility ради визуального эффекта; для анимаций учитывать reduced motion и возможность управления звуком.
- Не редактировать сгенерированные файлы: в проекте их нет, поэтому изменения должны оставаться в исходниках и `assets/`.

- Не называть сборку, линт или статический анализ доказательством визуальной и функциональной работоспособности.
